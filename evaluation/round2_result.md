## 2. 수정 사항

### 도구 ([src/tools.py](../src/tools.py), [data/topics.json](../data/topics.json))
- `get_topic_info`
  - 주제에 `aliases`(별칭)를 둡니다. "집", "아파트" → 거주 형태, "회사", "직장" → 직업, "자기 소개" → 자기소개
  - 후보가 여러 개면 후보 이름만 주던 것을, 후보의 상세 정보(최대 5개)를 모두 돌려주도록 바꿨습니다. 다시 조회할 필요가 없습니다.
- `get_level_criteria`: 문제 유형을 쉼표로 이어 여러 개를 한 번에 조회할 수 있습니다 (예: `"묘사, 과거 경험, 비교"`).

### 프롬프트 ([src/agent.py](../src/agent.py) `SYSTEM_PROMPT`)
- **키워드 검사**: `check_script`에는 사용자가 준 개인 경험 키워드만 넘기고, 키워드가 없으면 넘기지 않게 했습니다.
- **조회 규칙**
  - 자료 조회는 첫 턴에 한 번에 하고, 같은 도구를 다시 부르지 않습니다.
  - 주제 후보가 여러 개면 골라서 바로 씁니다.
- **분량 목표**: 문장 수와 단어 수 모두 가운데 값을 목표로 잡고, 한 문장의 평균 단어 수를 맞추게 했습니다.
- **콤보 세트**
  - 등급 기준은 한 번만 조회합니다.
  - 3개를 다 쓴 뒤 검사 3번을 같은 턴에 동시에 하고, 떨어진 것만 다시 고칩니다.
  - 키워드는 스크립트별로 나눠서 넘깁니다.
- **기본값**: 주제만 있으면 되묻지 말고 기본값(IM3)으로 바로 만들게 했습니다 (TQ006).

### 안정성 ([src/agent.py](../src/agent.py) `get_model`)
- Bedrock 요청 한도 초과 시 간격을 늘려 가며 최대 8번까지 자동으로 다시 시도합니다 (`botocore` adaptive retry).
- 분당 한도 초과처럼 잠깐 몰린 경우에는 오류 대신 조금 늦게 답합니다. 일일 한도가 소진된 경우에는 다시 시도해도 실패합니다.

### 설정 (`.env`)
- `us.anthropic.claude-sonnet-4-6`의 일일 한도가 먼저 소진되어 `BEDROCK_MODEL_ID`를 `global.anthropic.claude-sonnet-4-6`(같은 모델, 다른 라우팅)으로 바꿨습니다.

- 6개 모두 동작·분량 기준을 통과했고, **6개 모두 처음 쓴 스크립트가 바로 검사를 통과**했습니다 (Round 1에서 같은 6개는 1개가 재검사).
- 6개 모두 도구를 4번(조회 3개 동시 + 검사 1번), **2턴**으로 끝냈습니다. 주제 재조회와 `search_references` 추가 호출이 사라졌습니다.
- 한도 영향이 없었던 4개(TQ001~TQ004)의 평균 응답 시간은 18.2초 → **16.0초**로 줄었습니다.

### 거절 질의 9개
- 9/9 모두 도구 호출 없이 1초 안에 맞는 사유로 거절했습니다 (Round 1과 같음).

### 확인하지 못한 것
- **콤보 세트(TQ014, TQ015)**: 이번 개선의 핵심 대상이지만 한도 소진으로 실행되지 않았습니다.
  - 도구 단위로는 `get_level_criteria(question_type="묘사, 과거 경험, 비교")`가 가이드 3개를 한 번에 돌려주는 것을 확인했습니다.
- **개인화(TQ009~TQ013), 롤플레이, 돌발, 엣지 케이스**: 실행 오류로 채점하지 못했습니다.
- `evaluation/report.md`와 `results.json`에는 이번 부분 실행 결과(15/35 통과, 실패 20개는 모두 한도 오류)가 들어 있습니다.
